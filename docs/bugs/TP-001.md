## 1. Symptom

`jg -batch formal/fifo.tcl` dies at line 4, the `analyze` step:

```
[ERROR (VERI-1906)] rtl/front/input_fifo.sv(8): net type must be explicitly specified for 'clk' when default_nettype is none
[ERROR (VERI-1906)] rtl/front/input_fifo.sv(9): net type must be explicitly specified for 'rst_n' when default_nettype is none
[ERROR (VERI-1906)] rtl/front/input_fifo.sv(11): net type must be explicitly specified for 'wr_valid' when default_nettype is none
[ERROR (VERI-1906)] rtl/front/input_fifo.sv(12): net type must be explicitly specified for 'wr_data' when default_nettype is none
[ERROR (VERI-1906)] rtl/front/input_fifo.sv(14): net type must be explicitly specified for 'rd_ready' when default_nettype is none
[ERROR (VERI-1072)] rtl/front/input_fifo.sv(153): module 'input_fifo' is ignored due to previous errors
ERROR (ENL034): 6 errors detected in the design file(s).
ERROR: problem encountered at line 4 in file formal/fifo.tcl
```

Nothing elaborates, so zero properties are available and no proof can run. Xcelium compiles the same source, substitutes `wire`, and simulates correctly. Verilator is silent.

Lab machine, from the repo root at `08c0fdf`. The lab shell behaves as csh, so `|& tee`, not `2>&1 | tee`:

```

```

The same lines appear as warnings under Xcelium, which is the cheap way to see the full affected set without a formal licence:

```
make check SEEDS="1" SIM=xcelium
grep -h "NODNTW" logs/*_xcelium.log | sort -u
```

Evidence: `docs/qual/2026-10-28/jasper-fifo-analyze.excerpt.log`.

## 3. Root cause

In an ANSI port list, `input logic x` declares a *data type* and leaves the *port kind* unspecified, so the port kind defaults to the prevailing default net type. Under `` `default_nettype none `` there is no default net type, so the declaration is illegal — IEEE 1800-2017 s23.2.2.3.

Tool behaviour diverges because the standard's requirement is not uniformly enforced:

| Tool | Front end | Behaviour |
|---|---|---|
| JasperGold 2022.09 | Verific | error VERI-1906, module ignored |
| Xcelium 22.09 | `xmvlog` | warning NODNTW, substitutes `wire`, simulates |
| Verilator 5.020 | — | silent, even at `-Wall` |

Outputs are unaffected: `output logic` declares a variable, which needs no net type.

25 input ports across 5 files: `input_fifo` 5, `rr_arbiter` 4, `switch_allocator` 4, `fifo_sva` 9, `flit_driver` 3.

## 4. Fix

`input wire logic` on every input port — the net type explicit, the data type unchanged:

```systemverilog
input  wire logic             clk,          // was: input logic clk
input  wire logic [WIDTH-1:0] wr_data,
```

README rule 7 and the module template amended so new code starts correct.

Rejected: dropping `` `default_nettype none ``, which would restore the typo protection the directive exists to provide; and `` `default_nettype wire `` around the port list only, which hides the issue per-file instead of fixing it and still fails under any front end that reads the directive differently.

## 5. Escape analysis

**1. Which existing check should have caught this?** `make lint` runs Verilator `-Wall` with warnings fatal and is silent on it. CI runs the same, on every PR since #16, and was green throughout. Nothing in the flow was capable of catching it, because the flow had one front end.

**2. Was anything asserting the wrong behaviour as correct?** No. There was no claim about portability to assert against.

**3. What else in this class could still escape?** Everything only ever compiled by Verilator. This is the first time a second front end read the code, and it found a defect in 5 of 7 source files on the first attempt — in code that had passed lint and CI for weeks. Other candidates in the same class: `$clog2` in port widths, `typedef` visibility through `import`, the `step` time literal in `flit_if.sv` that Xcelium already flags as `SAWSTP`, and the opt-in clocking blocks. The structural fix is to run both front ends regularly, not to fix findings one at a time: Xcelium `-elaborate` on every merged test is now part of each lab session, and `analyze` on each new block is the entry condition for its formal run.

## 6. Collateral sweep

Pattern: `input` followed by a data type with no net type, under `` `default_nettype none ``.

```
grep -rn "input  *logic" rtl tb/sva tb/env
grep -h "NODNTW" logs/*_xcelium.log | sed 's/.*(\([^,]*\),.*/\1/' | sort -u
```

The Xcelium warnings are authoritative for scope and named all 5 files, including `tb/env/flit_driver.sv`, which a reading of the RTL directories alone missed. All 25 ports fixed in one PR; post-fix `grep` for bare `input logic` is clean. `rtl/pkg/noc_pkg.sv` has no ports and is unaffected.

Future blocks: `route_unit`, `input_port`, `vc_allocator`, `crossbar`, `output_unit`, `router_top` are all unwritten as of 2026-10-29 and must be written against the amended template, not retrofitted.
