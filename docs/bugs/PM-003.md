## 1. Symptom

No failure. Both tests pass at every seed, before and after the fix, which is what makes this
class of defect expensive: the regression reports green and the seed column is meaningless.

Observed directly by printing the first random flit of each checker at two seeds on the pre-fix
source:

```
+seed=1  PROBE FW=64 first-flit=ddfebffffdffffff   PROBE FW=32 first-flit=cf58c7a2
+seed=2  PROBE FW=64 first-flit=ddfebffffdffffff   PROBE FW=32 first-flit=cf58c7a2
```

Byte-identical. `make check SEEDS="1 2 3 4 5"` ran one stimulus five times and reported five passes.

## 2. Reproduce

On the pre-fix commit of either branch (`b51d2bc` for `tb_crossbar`, `b0ba389` for `tb_output_unit`;
post-fix `5f8176a` and `b8cb845`, tree-identical to squash merges `8b9bf45` and `9d77c0d`), fetched with
`git fetch origin pull/29/head:pr29 pull/30/head:pr30` because the branches are deleted, insert one line after `rand_data();` in the checker's first phase:

```systemverilog
$display("PROBE FW=%0d first-flit=%h", FW, xb_flit[0]);
```

then

```
make build TEST=tb_crossbar
obj_tb_crossbar/sim +seed=1 | grep PROBE
obj_tb_crossbar/sim +seed=2 | grep PROBE
```

Pre-fix the two outputs are identical; post-fix they differ. Verilator 5.020.

## 3. Root cause

Each checker instance seeded its own RNG from its elaboration-time parameter only:

```systemverilog
void'($urandom(SEED));            // pre-fix, in xb_chk / ou_chk
```

In SystemVerilog every module instance has its own RNG state, so seeding from a constant
parameter makes that instance's stream independent of anything passed at run time. The top level
did read the plusarg and call `$urandom(seed)`, but that seeds the *top* instance, which generates
no stimulus. The runtime seed therefore reached nothing.

`tb/tests/tb_rr_arbiter.sv` and `tb/tests/tb_switch_allocator.sv`, both already on `main`, do this
correctly: they read the plusarg inside the checker and combine it with the per-instance parameter.
The two new tests were written against the structure of those files but not against that detail.

## 4. Fix

Adopt the existing pattern, read inside the checker:

```systemverilog
if (!$value$plusargs("seed=%d", seed_v)) seed_v = 1;
seed_r = int'(seed_v * 1000 + SEED);   // runtime seed x per-instance offset
void'($urandom(seed_r));
```

The `* 1000` keeps the four configurations in one run on disjoint stream regions while letting the
runtime seed move all of them together. The redundant top-level seeding was removed.

Rejected: seeding only from the plusarg, which would give all four configurations in one simulation
the identical stream and lose the per-configuration independence the parameter was there to provide.

## 5. Escape analysis

**1. Which existing check should have caught this?** None can. A seed defect produces no failing
run: `make check` passes, CI passes, lint passes. The only signals are reading the code or
comparing stimulus across seeds, and nothing in the flow does either.

**2. Was anything asserting the wrong behaviour as correct?** Yes, indirectly. Both PR descriptions
claimed "seeds 1-5 PASS" as evidence of robustness. The claim was true and worthless: five runs of
one stimulus. The descriptions were corrected when the fix landed.

**3. What else in this class could still escape?** Any multi-instance testbench added from now on.
`tb_noc_pkg`, `tb_fifo`, `tb_fifo_link`, `tb_flit_if` and `tb_fifo_empty_read` should each be
checked against the two-seed probe above; this record does not claim they were. The structural
answer is a `make check` mode that runs one test at two seeds and fails if the logs are identical,
which would catch the whole class rather than one instance of it.

## 6. Collateral sweep

Pattern: `$urandom(` seeded from anything that is not derived from the `seed` plusarg.

```
grep -rn "urandom(" tb/tests/*.sv | grep -v "urandom()" | grep -v "urandom_range"
```

On `main` at `b2be922` this returns four sites: `tb_rr_arbiter` and `tb_switch_allocator` (both
already correct, `seed_v * 1000 + SEED`), and `tb_crossbar` and `tb_output_unit` (both fixed here).
No other test seeds its RNG explicitly. The sweep did not examine whether the tests that never call
`$urandom(seed)` are seed-sensitive at all; that is the open item in section 5.

## Note for the paper

A seeded regression that silently ran one stimulus five times, in a suite whose own PR descriptions
cited the seed count as evidence. It is a defect that no simulation run can surface, found by
reading the code against two files already in the repository that did it correctly. For the
detection matrix it belongs under REVIEW, and it is a concrete case where the technique columns
other than review would all have reported green.
