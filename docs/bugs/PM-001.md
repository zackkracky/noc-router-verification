## 1. Symptom

`a_p06_credit_iff_dequeue` fails on every seed at t=95 ns, the first dequeue:

```
P06 credit mismatch
```

`credit_out` is low in the cycle the dequeue is accepted and rises in the following cycle. Expected `credit_out == (rd_ready && rd_valid)` in the same cycle.

## 2. Reproduce

The two branches never coexisted on `main`, and the test was still `t_fifo` with no package and no per-test filelist, so `make` cannot reproduce it. Both commits survive in the PR refs. From any clone:

```
git fetch origin pull/13/head pull/17/head
git switch --detach f5ab0b9                                      # pre-fix input_fifo, t_fifo.sv
git checkout 7af0beb -- tb/sva/fifo_sva.sv tb/sva/bind_all.sv     # P01-P06 as first written
verilator --binary --timing --assert -Wno-fatal --timescale 1ns/1ps --top-module t_fifo \
  rtl/front/input_fifo.sv tb/sva/fifo_sva.sv tb/sva/bind_all.sv tb/tests/t_fifo.sv -o sim --Mdir obj
./obj/sim +seed=1
```

Expected: `[95000] ... a_p06_credit_iff_dequeue: P06 credit mismatch`. Re-run on 2026-11-03 with Verilator 5.020: fails at 95 ns on seeds 1, 2 and 3, as recorded. Signals: `clk`, `rd_ready`, `rd_valid`, `credit_out`, `do_read`, `count`, 90-110 ns. Seed-independent: the first dequeue reproduces it.

## 3. Root cause

`input_fifo` registered the credit:

```systemverilog
always_ff @(posedge clk) credit_out <= do_read;    // pre-fix
```

`INTERFACE.md` s6 specifies `credit_out` combinational in the dequeue cycle (`credit_out = deq`), and s5.3 places the single pipeline register in `input_port`. With a register in both, credit return to the upstream router takes 2 cycles instead of 1, which breaks the credit-loop latency the link handshake in s4 assumes.

## 4. Fix

```systemverilog
assign credit_out = rst_n && do_read;              // post-fix, PR #13
```

The `rst_n` term suppresses the credit during reset rather than relying on `do_read` being low.

Rejected: moving the register out of `input_port` instead, which would have matched the RTL to the implementation and left s4's credit-loop latency wrong. The spec was right; the RTL was wrong.

## 5. Escape analysis

**1. Which existing check should have caught this?** `tb_fifo` (then `t_fifo`) exercised the credit path and passed. It should have caught it and did not.

**2. Was anything asserting the wrong behaviour as correct?** Yes, and this is the more serious finding. Two checks in `t_fifo.sv` sampled `credit_out` one cycle *after* the dequeue, after `rd_ready` had already dropped: `"credit returned after dequeue"` (line 97 at `66eb0fe`, line 127 at `f5ab0b9`) and `"simultaneous read returns credit"` (line 217 at `66eb0fe`, line 247 at `f5ab0b9`). Both encoded the registered timing as expected behaviour. Per rule 4 of BUG_LOG.md they are a second defect, recorded as [PM-002](PM-002.md). The test was written by the RTL author alongside the RTL, so both carried the same misreading of s6. The test did not merely miss the defect; it asserted the defect was correct. An independent property contradicted a passing test.

**3. What else in this class could still escape?** Any signal whose timing is specified in `INTERFACE.md` but checked only by the owning block's own test. The structural answer is the ownership rule: cross-written assertions catch what co-written tests cannot. Credit accounting at the `input_port` and `output_unit` boundary (`A10`, `R13`, `R14`) is the next place this class can hide, and those are cross-owned by design.

## 6. Collateral sweep

Pattern: a specified-combinational signal implemented as a register. Searched all RTL on the branch for `always_ff` assignments to ports that `INTERFACE.md` lists as combinational:

```
grep -rn "always_ff" rtl/ | grep -i "credit\|valid\|grant"
```

At the time of the fix, `input_fifo` was the only merged block with a credit output, so the RTL sweep was clean by construction. The sweep did not cover the testbench, which is where the same misreading also lived: `grep -n 'check(credit_out' tb/tests/t_fifo.sv` at `f5ab0b9` lists both checks above, and only the first was named in this record until 2026-11-03. The pattern recurs as `input_port`, `output_unit` and `vc_allocator` land — each one's credit and grant outputs are checked against s5.3 and s7 at review, not only by its own test.

## Note for the paper

This is the project's cleanest methodology data point: a cross-written property contradicted a co-written unit test that passed on broken RTL. It supports the independence rule directly. It is pre-merge and must be reported as such — it is not one of the two counted bugs the Phase 2 exit requires.
