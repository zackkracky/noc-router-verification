## 1. Symptom

`a_p06_credit_iff_dequeue` fails on every seed at t=95 ns, the first dequeue:

```
P06 credit mismatch
```

`credit_out` is low in the cycle the dequeue is accepted and rises in the following cycle. Expected `credit_out == (rd_ready && rd_valid)` in the same cycle.

## 2. Reproduce

On `revu/input-fifo` at the pre-fix commit:

```
make build TEST=tb_fifo
make sim TEST=tb_fifo SEED=1 WAVES=1
make waves TEST=tb_fifo SEED=1
```

Signals: `clk`, `rd_ready`, `rd_valid`, `credit_out`, `do_read`, `count`. Look at 90-110 ns. Seed-independent — any seed that dequeues reproduces it on the first dequeue.

## 3. Root cause

`input_fifo` registered the credit:

```systemverilog
always_ff @(posedge clk) credit_out <= do_read;    // pre-fix
```

`INTERFACE.md` s6 specifies `credit_out` combinational in the dequeue cycle (`credit_out = deq`), and s5.3 places the single pipeline register in `input_port`. With a register in both, credit return to the upstream router takes 2 cycles instead of 1, which breaks the credit-loop latency the link handshake in s4 assumes.

## 4. Fix

```systemverilog
assign credit_out = rst_n && do_read;              // post-fix, PR #13
```

The `rst_n` term suppresses the credit during reset rather than relying on `do_read` being low.

Rejected: moving the register out of `input_port` instead, which would have matched the RTL to the implementation and left s4's credit-loop latency wrong. The spec was right; the RTL was wrong.

## 5. Escape analysis

**1. Which existing check should have caught this?** `tb_fifo` (then `t_fifo`) exercised the credit path and passed. It should have caught it and did not.

**2. Was anything asserting the wrong behaviour as correct?** Yes, and this is the more serious finding. `t_fifo` line 97 checked `credit_out` one cycle *after* the dequeue — it encoded the registered timing as expected behaviour. The test was written by the RTL author alongside the RTL, so both carried the same misreading of s6. The test did not merely miss the defect; it asserted the defect was correct. An independent property contradicted a passing test.

**3. What else in this class could still escape?** Any signal whose timing is specified in `INTERFACE.md` but checked only by the owning block's own test. The structural answer is the ownership rule: cross-written assertions catch what co-written tests cannot. Credit accounting at the `input_port` and `output_unit` boundary (`A10`, `R13`, `R14`) is the next place this class can hide, and those are cross-owned by design.

## 6. Collateral sweep

Pattern: a specified-combinational signal implemented as a register. Searched all RTL on the branch for `always_ff` assignments to ports that `INTERFACE.md` lists as combinational:

```
grep -rn "always_ff" rtl/ | grep -i "credit\|valid\|grant"
```

At the time of the fix, `input_fifo` was the only merged block with a credit output, so the sweep was clean by construction. The pattern recurs as `input_port`, `output_unit` and `vc_allocator` land — each one's credit and grant outputs are checked against s5.3 and s7 at review, not only by its own test.

## Note for the paper

This is the project's cleanest methodology data point: a cross-written property contradicted a co-written unit test that passed on broken RTL. It supports the independence rule directly. It is pre-merge and must be reported as such — it is not one of the two counted bugs the Phase 2 exit requires.
